1 Executive Summary

The Luminedge CRM is a purpose-built, full-stack Customer Relationship Management platform designed for Luminedge, an education and test-preparation company. Unlike generic CRM solutions, it is tailored to manage the complete lifecycle of student engagement — from initial lead capture through course enrollment, mock test scheduling, exam booking, university application processing, and ongoing communication.

The system is built on the MERN stack (MongoDB, Express.js, React/Next.js, Node.js) with TypeScript throughout both frontend and backend, ensuring type safety and developer productivity. It serves three distinct user roles — Admins, Business Development Managers (BDMs), and Students — each with a dedicated portal featuring role-specific dashboards, workflows, and data access controls.

The platform includes 19 API route groups, 16 database models, realtime push notifications via Socket.IO, built-in chat messaging, document management with cloud storage, client-side PDF and Excel report generation, and a comprehensive analytics dashboard.

ℹ️
The application is currently deployed with the frontend on Netlify, backend on Render.com (always-on Node process for Socket.IO), database on MongoDB Atlas, and file storage on Vercel Blob.

Security Note: The frontend Next.js middleware performs JWT decode only (no signature verification) — it is purely a UX routing layer. All actual data access authorization is enforced server-side by the backend auth middleware which performs full JWT signature verification.

Additional Auth Features

  • Google OAuth — Staff can sign in with Google via google-auth-library
  • Password Reset — Email-based flow using Nodemailer over SMTP
  • Rate Limiting — Auth endpoints limited to 20 requests per 15 minutes
  • Token Expiry — JWT tokens include exp claim; expired tokens are rejected

12 Key Observations & Recommendations

Strengths

#Observation
1Domain-specific design — Purpose-built for education CRM rather than a generic solution, with deep integration of student lifecycle workflows.
2Full TypeScript — Both frontend and backend use TypeScript, improving code quality, refactoring safety, and developer experience.
3Dual token separation — Staff and student auth use separate cookies, preventing token confusion and simplifying role-based access.
4Flexible deployment — Socket bridge pattern allows API and WebSocket server to run on the same or different hosts.
5Comprehensive security — Helmet, rate limiting, CORS, bcrypt, input sanitization, and request size limits all properly configured.
6Rich dashboard analytics — The 38 KB dashboard controller indicates extensive reporting and KPI tracking capabilities.
7Test infrastructure — Jest + Supertest + mongodb-memory-server provides a solid foundation for automated testing.

Areas for Consideration

#ObservationImpact
1 Dashboard controller complexity — At 38 KB, dashboard.controller.ts likely contains complex aggregation logic that could benefit from being split into focused service modules. Medium
2 Dual charting libraries — Both Chart.js and Recharts are included. Consider standardizing on one to reduce bundle size. Low
3 Frontend middleware JWT decode — Uses atob decode without signature verification. This is documented as intentional (UX-only), but worth noting for security reviews. Low
4 Mixed route mounting — Some routes are mounted at /api/specificPath while others use bare /api prefix (applications, chat, documents, milestones, news, appointments), making the API surface harder to discover. Low
5 Auth controller size — At 23 KB, it handles login, register, password reset, Google OAuth, and potentially more. Splitting into dedicated auth sub-controllers could improve maintainability. Medium
